## Подтверждённые облачные операции — 27.11.2026

Пользователь разрешил `universe-datastores.objects:update`; повторный `UpdateAsync` тестового permission-probe прошёл. Studio использовала `SK09_ISOLATED_TEST_V1` только в Universe 10779228953. Три последовательных Studio Play сессии одного UserId подтвердили запись и загрузку профиля; в первой сессии после автосохранения считан снимок 2 Cloudwood, 1 Skyglass, 5 SC; после второй — 3, 1, 5. После остановки lock отсутствовал.

Два клиента Studio с разными тестовыми UserId успешно сохранили раздельные записи после PlayerRemoving. На отдельном синтетическом ключе последовательные `UpdateAsync` вызовы отклонили конкурирующего owner и чужую запись, а правильный owner освободил lock. Это не демонстрирует конкурентную гонку двух настоящих серверов и не доказывает поведение при всех отказах облака. Начальный harness применил ключ длиннее 50 символов и получил error 102; повтор с новым более коротким ключом прошёл. Основные ключи профиля в использованных сценариях ограничение не превысили.

Universe `10779228953`, Place `88188721882111`, имя `SKYKEEPERS_STAGE_09_DATA_TEST`; интерфейс создания сообщил «Only available to you and your collaborators». Пользователь включил Studio API Access именно в этой Experience. Тест `GetAsync` на отдельном пустом ключе `stage09_permission_probe_20261127` в `SK09_ISOLATED_TEST_V1` вернул nil; попытка `UpdateAsync` этого ключа отклонена ошибкой `502 ... Access forbidden`. Запись в реальный профиль не выполнялась. По инструкции Roblox MCP при таком ответе нужно разрешение `universe-datastores.objects:update`; до его получения обходить блокировку через Play или другое API нельзя.

Конфигурация `cloud-test.project.json` привязана к `SessionInventoryCloudTest.luau`, где установлен и проверяется точный тестовый Universe ID. Она собрана Rojo, но не подключена. При ошибке budget-функции сервис теперь завершает загрузку безопасно после ограниченных повторов; 29 mock-сценариев прошли. Реальные ограничения, одновременные серверы, вызовы и аварийный rollback пока не проверены.

## Продолжение

Текущий игровой adapter остаётся mock-only. `IsolatedCloudStore` добавлен в качестве неактивированного адаптера: он проверяет ожидаемый ненулевой UniverseId, использует отдельное имя хранилища и префикс тестовых ключей, сохраняет metadata/user IDs при UpdateAsync и проверяет бюджеты StandardRead и StandardWrite. Это не подтверждает его облачную работоспособность и не защищает от ошибочного указания UniverseId основной игры — перед включением необходимо независимо установить и сверить ID отдельной тестовой Experience. Создание или изменение данных production запрещено.

Внутри текущей версии actions запрещены во время SAVING и после BLOCKED; успешное обновление lease и проверка owner внутри UpdateAsync проверены только на mock. Сохранения не являются гарантированной транзакцией между памятью и облаком; при сбое после возможной записи результат может быть неопределённым. Mock не моделирует все сетевые отказы и гарантии Roblox. Автосохранение 180 сек не гарантирует верхнюю границу потери данных при отказе сервиса или аварии.

## Предыдущее состояние

Подключения к Roblox Cloud и изменений настроек API не было. Изучены официальные [Data stores](https://create.roblox.com/docs/cloud-services/data-stores), [player data and purchasing](https://create.roblox.com/docs/cloud-services/data-stores/player-data-purchasing) и [лимиты](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits). UpdateAsync требует callback без yield, может отменить запись через nil, расходует бюджеты чтения и записи. Studio может обращаться к тому же хранилищу, что опубликованная игра; для настоящего тестирования нужна отдельная Experience.

Экспериментальный lease 900 с и проверки owner/expiry внутри чистых преобразований исследуются только с mock. До использования нужны контролируемый heartbeat, уникальный токен для каждой сессии, строгий запрет действий после потери lease, защита от незавершённых запросов, оценка часов серверов и тесты повторного вызова callback. Локальный mock не моделирует повтор callback, реальные задержки, ограничения и отказы после возможной записи. Без этих мер и интеграционного аудита профиль использовать нельзя.
